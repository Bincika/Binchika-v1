# Tenant configuration: running Binchika for your country

This repository ships with **Exampleland, a fictional country**, so that a fresh copy builds and runs. Every area, party, date and figure in it is invented. **Replace all of it before using this for a real election.**

The tenant file is the source of country values. Code reads `TENANT.…`, generated by the build from `tenants/<id>/tenant.json`. `tenant_config.json` says which tenant is active:

```json
{ "tenant": "example" }
```

The build (`node scripts/build-site.mjs`) checks the tenant, then writes `functions/_lib/tenant.generated.js` (also copied for the browser) and `site/data/locale.json`.

## What a fork replaces
| What | Where |
|---|---|
| Country, electoral body, time zone, polling-station codes, rules, wording | `tenants/<id>/tenant.json`. Start from `tenants/_template/tenant.json`: the build refuses it until every `FILL` is replaced |
| Areas, parties, races, elections, register baseline | `site/data/`. Keep the file shapes. `node scripts/validate-data.mjs` checks them |
| Page text | `src/pages/` and `src/kb/`. Keep the "only the electoral body declares results" notice on every page. Tokens such as `{{BODY}}`, `{{COUNTRY}}`, `{{PORTAL}}` and `{{RESULT_FORM}}` come from the tenant |
| Verifier seats and areas | `supabase/migrations/0002_seed.sql`, `0004_seats.sql`, `0010_szv_recalibration.sql`. `scripts/gen-seats-sql.mjs` shows the pattern |
| Privacy notice | `src/pages/privacy.html` is a template, not a notice |

## Things to know
- **Exampleland copies the shape of a real deployment:** 37 areas in six groups, so seat lists and code formats keep working. Change the shape to fit your country, along with its seats and tests.
- **Field names are a contract.** `irev`, `ec8a` and `vin` are API and database field names from the first deployment. They do not mean a fork uses those systems, and renaming them breaks consumers of the press feed.
- **Result-sheet checks and the winning-rule display are your responsibility.** `functions/_lib/ec8a.js` holds the sheet arithmetic. Write your country's legal rules with their sources, and tests for them.
- **Applications stay closed** unless `APPLICATIONS_OPEN` and `PRIVACY_NOTICE_VERSION` are both set. Set them only when your own privacy notice is in force.

## Standing up a new country
1. Fork this repository. You may use either licence, MIT or Apache 2.0. Keep `LICENSE-MIT`, `LICENSE-APACHE` and `NOTICE`.
2. `cp -r tenants/_template tenants/<iso>`, fill every `FILL` with a sourced value, and set `"tenant": "<iso>"` in `tenant_config.json`.
3. Replace `site/data/` and rewrite `src/pages/` and `src/kb/`.
4. `node scripts/build-site.mjs`, `node scripts/validate-data.mjs`, then `node --test tests/*.test.mjs`. Some test fixtures use Exampleland's values; they tell you what to change.
5. Your own accounts and identifiers:
   - a Cloudflare D1 database (`wrangler d1 create`; put its id where the `wrangler.toml` files say `REPLACE`);
   - an R2 bucket;
   - a Supabase project (in `.env`, and its address in `site/_headers` where it says `YOUR-PROJECT`);
   - the SHA-256 of your administrator's address in `functions/_lib/supa.js` and the admin-lock migration. Never commit the address itself.
6. `git config core.hooksPath scripts/hooks` (secret guard). Secrets go in `.env` and your providers' secret stores, never in git.
