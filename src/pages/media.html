For newsrooms and civic organisations

Use our citizen tallies, correctly.

Before this goes on air

You may show these figures only with all three lines on screen. On radio or television, also say them aloud.

  • Notice: “Citizen-verified tallies. Only EEC declares results.”
  • Coverage: “in N of 12,000 polling units” (president, Senate, House) or “from N polling units in the states voting” (governor, state assembly). One state: “from N polling units in Region LA”, never “Region LA governorship result”. N is the number of published units.
  • Source and time: “Source: Binchika (binchika.com). Feed time 21:05 XLT.” Use the time your developer reads from the feed, not the studio clock. Never “as of 21:05”: the figures can be older.

Never present the figures as official results, a projection or a winner. Only EEC declares election results in Exampleland. Do not call the party with the most votes “leading”, “ahead” or “trending”, and do not highlight, colour or tick it. Published units are not a random sample.

  • Percentages and bars: allowed only as well as those three lines, with this label beside them: “Citizen-verified vote shares from published units only. Not results, projections or winners.” If sorted by votes, also label the list “by citizen-verified votes so far”. Do not use party brand colours.
  • Frozen or stopped feed: ask your developer to build the 12-minute check, which the code examples include. If it fires, or the feed fails, add “These figures may be out of date” beside the feed time. Without that check, always add those words.
  • Zero published units: do not show zeros as votes. Say: “No citizen-verified tallies have been published yet. Only EEC declares results. Source: Binchika (binchika.com).”
  • Figures can go down after a correction, or if a unit is held after a failed check.

Binchika publishes citizen-verified polling-unit tallies as an open, read-only feed. Any newsroom can use it today, without a key. Registered desks also get a named contact for corrections and notice before the feed changes.

These are not results. Only EEC declares election results in Exampleland. Binchika never declares a winner and never projects one.

What the feed is

  • Vote totals from polling units whose citizen tally passed every check: at least three separate citizen reports of the same posted result sheet, at least 85% agreement, confirmed by a trained Binchika volunteer (a verifier), and figures on the sheet that add up. Units that fail a check appear in the unit counts but not in the vote totals.
  • Aggregates only: national and per-state totals, unit counts, and how many units have a citizen tally that does not match the result sheet EEC published on ERP, EEC's online result-viewing portal. A difference is not proof of wrongdoing: report it as “does not match”, never as fraud. No photographs, no names, no personal data.
  • Every published unit is in the public, tamper-evident ledger, so you can check any figure yourself.
  • Local government elections are run by the State Independent Electoral Commissions (local election boards), not EEC. They are not in the feed.

Connect

One address per race: president, senate, house, governor or state-assembly. JSON, open to any origin. The figures update at most once a minute. A new copy of the JSON is made at most every 15 seconds, so checking more often returns the same copy, and checking every 30–60 seconds is enough. See how old the figures are.

Example in JavaScript and Python 
const lastGood = {};    // one copy per race; keep it between checks
const lastMoved = {};   // when each race's updatedAt last changed
const TWELVE_MINUTES = 12 * 60 * 1000, TWO_MINUTES = 2 * 60 * 1000;

// stale is true when this check failed or the figures look frozen or stuck. feed is your last good copy, or undefined if you have none.
async function check(race = "president") {
  let failed = true;
  try {
    const r = await fetch(`https://binchika.com/api/press/snapshot?race=${race}`, { signal: AbortSignal.timeout(10000) });
    if (r.ok) {
      const next = await r.json();
      if (next.updatedAt !== lastGood[race]?.updatedAt) lastMoved[race] = Date.now();
      lastGood[race] = next;
      failed = false;
    }
    // 503 or other 5xx: keep lastGood and try again in 15–60 seconds. 400 or 404: fix the address.
    else console.warn("Feed answered", r.status);
  } catch (error) { console.warn("Feed not reached", error.name); }   // the same: keep lastGood
  const feed = lastGood[race];
  // The 12-minute check. Both times come from our clock, so yours cannot cause a false alarm. Up to about 10 minutes apart is normal when nothing has changed.
  const frozen = Boolean(feed) && Date.parse(feed.updatedAt) - Date.parse(feed.figuresBuiltAt) > TWELVE_MINUTES;
  // A copy stuck on its way to you: updatedAt has not moved for 2 minutes while you keep checking.
  const stuck = Boolean(feed) && Date.now() - lastMoved[race] > TWO_MINUTES;
  return { feed, stale: failed || frozen || stuck };
}

const { feed, stale } = await check();
if (feed) {
  if (feed.units.published === 0) {
    console.log("No citizen-verified tallies have been published yet. Only EEC declares results. Source: Binchika (binchika.com).");
  } else {
    // Always show feed.notice next to the figures. It is the required line:
    // "Citizen-verified tallies. Only EEC declares results."
    // Take the feed time from the copy you hold, never your own clock.
    const time = new Date(feed.updatedAt).toLocaleTimeString("en-GB", { timeZone: "Etc/GMT-1", hour: "2-digit", minute: "2-digit" });
    // This coverage line is for president, Senate and House. See the terms of use for the other races.
    console.log(feed.notice, `In ${feed.units.published} of 12,000 polling units`, feed.national.totals);
    console.log(`Source: Binchika (binchika.com). Feed time ${time} XLT.`);
  }
  if (stale) console.log("These figures may be out of date.");
}
import requests
from datetime import datetime, timedelta, timezone
from time import monotonic

last_good = {}   # one copy per race; keep it between checks
last_moved = {}  # when each race's updatedAt last changed

def utc(text):
    return datetime.fromisoformat(text.replace("Z", "+00:00"))

# stale is True when this check failed or the figures look frozen or stuck. feed is your last good copy, or None if you have none.
def check(race="president"):
    failed = True
    try:
        r = requests.get("https://binchika.com/api/press/snapshot",
                         params={"race": race}, timeout=10)
        r.raise_for_status()
        new = r.json()
        if new["updatedAt"] != last_good.get(race, {}).get("updatedAt"):
            last_moved[race] = monotonic()
        last_good[race] = new
        failed = False
    except requests.RequestException as error:
        # 503 or other 5xx, or no connection: keep last_good and try again in 15-60 seconds.
        # 400 or 404: fix the address.
        print("Feed problem:", error)
    feed = last_good.get(race)
    # The 12-minute check. Both times come from our clock, so yours cannot cause a false alarm. Up to about 10 minutes apart is normal when nothing has changed.
    frozen = bool(feed) and utc(feed["updatedAt"]) - utc(feed["figuresBuiltAt"]) > timedelta(minutes=12)
    # A copy stuck on its way to you: updatedAt has not moved for 2 minutes while you keep checking.
    stuck = bool(feed) and monotonic() - last_moved[race] > 120
    return feed, failed or frozen or stuck

  • national.totals: party acronym → votes, from published units only. The feed gives no shares. For a percentage, divide a party's votes by all parties' votes in the same totals, and add the label given in the box at the top of this page.
  • byState: one entry per ISO 3166-2 state code (XL-AB … XL-ZA; the Capital Region is XL-FC), each { "units": n, "totals": { … } }, where units is the number of published units in that state.
  • units.published: units in the totals. lowerConfidence: agreement too low to count. held: failed a posting check (for example totals that do not add up). notYetHigh: still waiting for enough reports. Only published units are in the votes.
  • Coverage. The denominator is EEC's count of polling stations (12,000). Use “units.published of 12,000” only for the president, Senate and House races. Not every state elects a governor on the same day, and the Capital Region has no State House of Assembly, so for governor and state-assembly races state the count instead: “from 1,240 polling units in the states voting”. The feed has no per-state polling-unit total, so for a state also state the count: “from 312 polling units in Region LA”.
  • For Senate, House, governor and state-assembly races, national.totals adds up party votes across constituencies or states. It is not seats and not a result for any constituency or state. In Senate, House and state-assembly races each byState entry adds up the published units from every constituency in that state that has any, so label it that way, for example “all Senate districts in Region LA combined”, never as if the state were one contest. In a governor race each byState entry is that state's one contest, from published units only: label it “from N polling units in Region LA”, never as that state's result.
  • byState lists only states with at least one published unit. A missing race means president.
  • ledger.head is null until the first unit is published. The ledger head and count are read when the copy is made, so they can include units that are not in the totals yet.
  • updatedAt (UTC; add one hour for XLT) is when this copy of the JSON was made. Show it from the copy you hold, never your own clock, as “Source: Binchika (binchika.com). Feed time 21:05 XLT.”
  • figuresBuiltAt (UTC) is when our last update built these figures. The two times can be up to about 10 minutes apart when nothing has changed. If figuresBuiltAt is more than about 12 minutes older than updatedAt, our update has stopped or is delayed: show “These figures may be out of date”. This is the 12-minute check. Compare these two times, not your own clock. If updatedAt itself has not moved for about 2 minutes while you keep checking, treat that the same way.
  • Errors: 400 for an unknown race; 404 for a wrong URL path; 5xx means try again after 15–60 seconds and keep showing your last good copy, labelled as described under how old the figures are. If you have no good copy yet, show no figures.
  • 503 with {"error":"results temporarily unavailable"} means the figures for that race are missing or more than 20 minutes old.

How old the figures are

  • Normally: up to about 75–90 seconds old, counted from when a polling unit passes its checks: up to a minute until our next update, and up to about 15–30 seconds to build and serve it. Add the time since you last checked the feed. Reports and checks before that take longer, and this page gives no figure for them.
  • If our scheduled update stops: the figures stop changing, but the feed keeps answering and its feed time keeps moving. So figures can be up to about 12 minutes old, plus the time since you last checked, before anything shows it. Your developer can spot a stoppage, because the feed also says when its figures were built: ask them to build this check, which the code examples include. When that is more than about 12 minutes before the feed time, show “These figures may be out of date” beside the feed time. A gap of up to about 10 minutes is normal: when nothing has changed, we rebuild the figures only every 10 minutes. After 20 minutes the feed returns an error, rather than keep presenting old figures as current.
  • The time to show: “Source: Binchika (binchika.com). Feed time 21:05 XLT.” Feed time is when the feed made the copy you are showing, in Exampleland time. It is not the studio clock and not the moment you pulled the figures. On radio or television, say it aloud. Do not say “as of 21:05”: the figures can be older than that. Never describe them as up to the minute or just updated.
  • If the feed returns an error or cannot be reached: keep your last figures up only with that same time and the words “These figures may be out of date”. They get older for as long as the problem lasts, and how long to keep them up is your editorial decision. If you have no earlier figures, show none.

Terms of use

  1. Show “Citizen-verified tallies. Only EEC declares results.” beside the figures, every time.
  2. Credit Binchika (binchika.com).
  3. Never present the figures as official results, a projection or a winner.
  4. Always state coverage. President, Senate and House: “in N of 12,000 polling units”. Governor and state assembly: “from N polling units in the states voting”. One state: “from N polling units in Region LA”.
  5. Senate, House, governor and state assembly: the figures add up votes from many separate contests. They are not seats and not a result for any constituency or state. Say “party votes across all Senate districts with published units” or “all Senate districts in Region LA combined”, never “Region LA Senate result”. For governor, one state's figures are one contest: say “from N polling units in Region LA”, never “Region LA governorship result”.

Say, for example, for the presidential race: “In 1,240 of 12,000 polling units, citizen-verified tallies show Party X with 52,310 votes and Party Y with 48,920. Only EEC declares results. Source: Binchika (binchika.com). Feed time 21:05 XLT.” Don't say: “Party X leads”, “X is winning” or “projected winner”, and do not call the party with the most votes “leading”, “ahead” or “trending”. Published units are not a random sample and do not show the national picture. On screen, do not highlight, colour or tick the party with the most votes; if you sort parties by votes, label the list “by citizen-verified votes so far”. If you show percentages or bars, add this label as well as the required lines: “Citizen-verified vote shares from published units only. Not results, projections or winners.” Do not use party brand colours. Always state coverage. On radio or television, say the notice aloud.

The same terms apply to every outlet: no exclusives, no paid tier, no early access.
